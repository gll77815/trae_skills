# 风格 B — 月度复盘式（目标 vs 实际 + 偏差归因）

核心是一张"目标 vs 实际"表格，加状态灯加归因，最后一行总结下月动作。

## 字号锚点

| 元素 | 字号 |
|---|---|
| 主标题 | 24pt |
| 段标（本月结论/目标vs实际） | 16pt |
| BLUF 一句话 | 18pt 加粗 |
| 表头 | 14pt |
| 表格正文 | 13pt |
| 归因 | 12pt |
| 下月动作行 | 14pt |

## 表格规则

- 列宽建议：指标 200 / 目标 100 / 实际 100 / 状态 80 / 归因 360（剩余）
- 行高 32-36px，足够呼吸
- 状态列只放圆点（🟢/🟡/🔴/⚪），不要文字"绿/黄/红"——浪费空间
- 归因列**只在 黄/红 行填写**，绿色行留空或写"-"
- 行数控制在 **4-6 行**，多了听众消化不了；超过时拆到附录页

## 何时用这个风格

- 月度/季度复盘
- 听众是直属领导或跨部门同级
- 内容包含可量化 KPI 且有目标对比
- 不适合：项目里程碑（用 project-milestone）、给董事会（用 BLUF）

## 实现要点

### BLUF 的视觉处理

左侧 4px 蓝色高亮条，文字 18pt 加粗，**第一句必须包含整体颜色判断**（"整体黄灯/绿灯/红灯"）。这是给老板的第一眼锚定。

### 表格的"信息分层"

老板扫表的顺序通常是：状态列 → 偏差列 → 数字列。所以：

- 状态灯必须显眼（实心圆点，不用图标）
- 偏差归因不需要长篇，一句话讲清楚根因 + 你已经/即将做什么

### 下月动作的写法

- 必须有序号 ①②③（视觉锚点）
- 每个动作必须 含动作 + 责任人 + deadline，三件套缺一不可
- ≤3 个动作。多了说明你没收敛。其他放附录页"备而不讲"。

## 不要做的事

- ❌ 把目标列和实际列合并成"5.0%（target 3%）"：眼睛找不到比较锚点
- ❌ 状态列用文字"绿/黄/红"而不是圆点：浪费宽度
- ❌ 归因写一长段：归因目的是让老板"理解 + 信任你已经在处理"，不是详细论证
- ❌ 没有下月动作：复盘不指向行动 = 复盘无用
