# 风格 C — 项目里程碑式（横向 timeline + 状态灯）

横向时间线展示项目阶段，每个里程碑标完成/进行/未来，下方挂当前风险与下一里程碑动作。

## 配色

| 元素 | 颜色 | 说明 |
|---|---|---|
| 背景 | `#FFFFFF` | 白 |
| Timeline 主线 | `#E5E7EB` | 浅灰 2px 横线 |
| 已完成节点 | `#22C55E` | 绿色 12px 圆点 |
| 进行中节点 | `#F59E0B` 或 `#3B82F6` | 黄（有风险）/ 蓝（顺利） |
| 未来节点 | `#CBD5E1` | 灰，空心圆或浅色实心 |
| 阶段名（已完成） | `#1F2937` | 深灰，正常 |
| 阶段名（进行中） | `#1F2937` 加粗 | 深灰加粗 + 下划线 |
| 阶段名（未来） | `#94A3B8` | 浅灰 |
| 风险标 ⚠ | `#F59E0B` | 黄 |
| 分隔线 | `#E5E7EB` | 浅灰 |
| 当前风险段 | 见全局状态灯规范 | 与 weekly-status 一致 |

## 字号锚点

| 元素 | 字号 |
|---|---|
| 主标题 | 24pt |
| 整体健康度状态灯文字 | 16pt |
| 副信息（PM/期/阶段） | 12pt |
| Timeline 阶段名 | 18pt |
| Timeline 时间标签 | 12pt |
| Timeline 风险小标 | 11pt |
| 段标（当前风险/下一里程碑） | 16pt |
| 风险/动作正文 | 13pt |

## Timeline 布局规则

- 总宽 880px，从 x=40 到 x=920
- **5 个节点等分**：x = 40, 260, 480, 700, 920（240px 间距）
- 节点圆点 12px 半径
- 节点上方紧贴阶段名（y=210），下方紧贴时间标签（y=234）
- 进行中节点下方再加一行风险小标（y=258，如"⚠ 偏期 1 周"）

## 何时用这个风格

- 项目阶段汇报（立项/需求/实施/测试/上线 这类有清晰阶段感的项目）
- 跨阶段汇报（如季度初汇报项目从立项到中期的状态）
- 需要明确"我们走到哪儿了 + 下一里程碑在哪"

## 实现要点

### 进行中节点的特殊处理

进行中的节点是页面焦点：

- 圆点尺寸略大（14px vs 其他 12px）
- 阶段名加粗 + 下划线
- 下方挂一行风险/偏期小标（如"⚠ 偏期 1 周"）
- 颜色用黄（有风险）或蓝（顺利），不用绿（绿留给已完成）

### 已完成节点的处理

- 阶段名后面加 `✓` 标记
- 时间标签用过去式（如 W12 ✓）
- 不需要挂任何细节信息

### 当前风险段的格式

每条风险用 `🟡` 或 `🔴` 开头，紧跟一行说明 + 影响 + 你已经/即将做的事。**红色风险必须紧跟 "→ 需 XXX" 的 ask**。

### 下一里程碑段的写法

- 必须明确"什么时候进入下个阶段"（W22 进入测试期）
- 列 3 个以内最关键的下阶段动作，每个含责任人 + deadline
- 不要列 10 个微动作——让听众抓不到重点

## 不要做的事

- ❌ 用 4 个或 6 个节点（视觉不平衡，5 个是甜点）
- ❌ 用环形/曲线 timeline（炫技,不利于扫读）
- ❌ 已完成节点占据视觉重心（应该是进行中节点）
- ❌ 不写整体健康度状态灯：老板第一眼想看的就是"这项目稳不稳"
- ❌ 风险只列"有风险",没有量化影响和 deadline：等于没说
