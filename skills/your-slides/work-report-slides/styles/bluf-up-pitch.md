# 风格 D — BLUF 向上汇报式（一句结论 + 3 要点 + ask）

给老板/董事会的极简汇报：一句话结论占顶 → 3 个支撑要点（每个一句话+一个数字） → 明确的 ask。听众"不在乎过程，只在乎决策"。

## 字号锚点

| 元素 | 字号 |
|---|---|
| 顶部极简头 | 14pt |
| BLUF（一句结论） | 32-36pt |
| 要点主文字 | 18pt |
| 要点注解 | 12pt |
| Ask 段 | 14pt 加粗 |

## 何时用这个风格

- 向 CEO / CTO / VP 等高层汇报
- 董事会汇报、投资人沟通
- 跨业务线高管会
- 听众**没时间看细节**，需要一眼抓重点 + 一句话决策

## 实现要点

### BLUF 的写法

BLUF 必须是**一句话结论 + 决策诉求**：

✅ "上周整体绿灯，但 A 项目需本周拍板是否申请客户延期 (¥200K 合同节点)"
❌ "上周完成了 A 项目的数据迁移工作并修复了 B Bug" → 这是事实陈述，不是结论
❌ "我们一切都好，没什么问题" → 没决策诉求，老板会问"so what？"

BLUF 长度可以是 1-2 行，但**第一行必须能独立成立**（如果第二行被裁掉也能读懂）。

### 3 个要点的写法

固定结构：`序号 + 主题 ━━ 数字 + 状态灯` + 下一行**一句话**注解

- 主题用名词（"用户增长""重大事故""团队节奏"），不用动词
- 数字必须有变化方向（↑/↓ + 百分比），让老板秒判趋势
- 注解一句话内含因+果或现状+动作，**禁止超过 25 字**

### Ask 段的特殊处理

Ask 段是这种风格的**收尾压轴**。放底部，加深色横线分隔，必须包含：

- **谁要决策**："老板今天内决定"
- **决策什么**："A 项目是否申请客户延期"
- **不决策的代价**（如果空间允许）："否则 W19 内会触发违约"

如果本期没 ask，**明说**：`本周无需决策，仅同步进展`。**不要硬凑** ask，老板讨厌"无中生有的求决策"。

## 不要做的事

- ❌ BLUF 超过 2 行：老板看不完
- ❌ 3 个要点变成 5 个要点：超过 3 个就该用别的风格
- ❌ 没有 Ask 段还硬凑：老板会觉得你"为汇报而汇报"
- ❌ 要点的注解写成两行长句：极简风格的核心是"每个字都不浪费"
- ❌ 顶部加 logo 或装饰：BLUF 是这页第一眼锚点,前面任何元素都是干扰
- ❌ BLUF 居中：左对齐才符合阅读顺序,居中是仪式感不是决策感
