# Design Plan Template — 工作汇报方案输出模板

用户没看过这份方案前，**禁止动手生成页面**。汇报场景的方案审稿就是"老板视角预演"——把决策点、追问点提前过一遍，比改 PPT 便宜 10 倍。

---

## 标准输出格式

```markdown
## 设计方案（请确认后我再生成）

### 风格 & 听众
- 风格：[周报式 / 月度复盘 / 项目里程碑 / BLUF 向上汇报]
- 听众层级：[团队 / 跨部门 / 直属领导 / 高管董事会]
- 状态灯口径：[三色 / 四色 / 不用]
- 输出格式：[HTML / PPTX-OfficeMCP / PPTX-Standalone / PNG]

### BLUF（一句话结论，≤30 字）
> [核心结论。例：W18 整体绿灯,但 A 项目卡在 X 决策上,需本周给出方向]

### 支撑指标（3-5 个）
| 指标 | 目标 | 实际 | 状态 | 归因（黄/红必填） |
|---|---|---|---|---|
| 新增用户 | 10K | 11.2K | 🟢 | — |
| 付费转化 | 3% | 2.4% | 🟡 | 新引流渠道质量低于预期,W19 调整投放 |
| 重大事故 | 0 | 1 | 🔴 | A 项目数据迁移失败,已回滚,待复盘 |

### 行动项（3 个以内）
| 动作 | 责任人 | Deadline |
|---|---|---|
| 完成 A 项目复盘并提迁移方案 v2 | @张三 | 2026-W19 周三前 |
| 调整付费转化投放配比 | @李四 | 2026-W19 内 |

### 风险 / Ask（明确告诉听众"我需要 XXX"）
> [如有,例：A 项目数据迁移延期会影响 Q3 合同节点,需老板今天内决定是否申请客户延期]

### 视觉结构（粗略描述）
- 顶部：[周期标题 + 总状态灯,如"W18 周报 🟢"]
- 中部：[3 栏布局/表格/timeline/单一BLUF]
- 底部：[行动项 + Ask]
- 是否有附录页（备而不讲）：[是 / 否]

### 配色
- 背景：[白底（默认）/ 深灰底]
- 主文字：[#1F2937（默认）]
- 状态灯：🟢#22C55E / 🟡#F59E0B / 🔴#EF4444 / ⚪#94A3B8（统一,不改）
```

---

## 写 BLUF 的几条铁律

1. **必须是结论，不是事实陈述**：
   - ❌ "W18 上线了 3 个新功能" → 这是事实
   - ✅ "W18 整体绿灯,但 A 项目卡在 X 决策上,需本周拍板" → 这是结论

2. **≤30 字**：超长意味着"还没想清楚"。如果觉得 30 字说不完，说明结论本身太散，需要再收敛一次

3. **如果有红/黄状态，BLUF 必须提**：BLUF 是听众一眼扫到的，藏问题等于坑自己

4. **避免 hedge 语气**："基本/大致/感觉/可能"出现 ≥2 次就要重写

## 写指标的几条铁律

1. **目标 vs 实际必须配对出现**：只写"新增 11.2K"没有目标对比，听众不知道这数字好不好
2. **黄红状态必须有归因**：归因写一行就够，不要长篇大论
3. **指标数控制 3-5 个**：多了听众消化不了，3 个是甜点
4. **数字格式统一**：要么都带千分位逗号，要么都不带；金额单位（K/M/万）全页一致

## 写行动项的几条铁律

1. **必须有责任人**：`@姓名` 或 `[团队]`，不允许"我们/大家"
2. **必须有 deadline**：用 W 周编号、月份或具体日期，**不允许"近期/尽快/ASAP"**
3. **必须是可验证的动作**：
   - ❌ "推进 A 项目" → 不可验证
   - ✅ "完成 A 项目复盘文档并提交 v2 迁移方案" → 可验证

## 写 Ask 的几条铁律

1. **必须明确"我需要听众做什么"**：决策？资源？时间？背书？
2. **不要藏在风险段落里**：单独成段，否则听众扫一眼就翻页了
3. **deadline 要写**：什么时候之前要这个决策？

## 用户确认的提问模板

输出方案后**最后一句必须是这个**：

```
以上是设计方案,可以开始生成了吗?或者哪里要改?
  □ 可以开始
  □ 改 BLUF
  □ 改某个指标（请说名字）
  □ 改行动项 / 责任人
  □ 改 ask
  □ 改输出格式
```

用户明确"可以"再进入实现。
