# Interaction Protocol — 必做的提问顺序

work-report-slides 的每一次调用都按以下顺序走完。**不要跳步**——汇报场景的失败成本是老板/同事在会上看你"现挂"，比发布会场景更尴尬。

---

## Step 0 — 保留策略（每次都必问）

修改/生成之前先问：

```
你希望我怎么处理当前页面？
  □ 复制当前页面再修改（推荐,默认）
     —— 我会先 duplicate 一份,在副本上动手,原页保留
  □ 直接修改当前页
     —— 在原页上改,无法回退（除非用 PPT 撤销）
  □ 新建一页（不动任何已有页面）
     —— 适合"加一页结论页 / 加一页风险页"
```

用 `ask_user_question` 提问。**默认是"复制再改"**。

为什么默认是复制：工作汇报版本迭代极频繁——周一改完周三 1on1 又改，老板经常一句"还是上版那种看板格式好"就让你回滚。保留副本是最低成本的安全网。

例外：当 Step 1 识别意图是"新建一页"时跳过本步。

---

## Step 1 — 识别意图

读 `<user_context>.selectedSlides` 和用户原话：

| 情况 | 意图 |
|---|---|
| 选中 1 页，说"改/重做/优化这页" | **单页重做** |
| 没选页，说"加一页结论页/加一页风险页/补一页行动项" | **新建一页** |
| 说"做一份周报/月报/季度汇报/项目复盘" | **多页汇报序列** |

不清楚时用 `ask_user_question` 问一句。

---

## Step 2 — 风格三连问（必做）

一次性问完，不要分多轮：

```
Q1 汇报风格 (单选)
  - 周报式            三栏(Done/Plan/Risk) + 总状态灯,适合团队周会
  - 月度复盘式        目标 vs 实际表格 + 状态灯 + 偏差归因 + 下月动作
  - 项目里程碑式      横向 timeline + 完成/进行/未来标记 + 当前风险
  - BLUF 向上汇报式   一句结论 + 3 支撑要点 + 明确 ask,适合给老板/董事会

Q2 听众层级 (单选,影响详略口径)
  - 团队内部          同事看,可以放细节、@责任人
  - 跨部门            兄弟部门看,要补背景、降术语
  - 直属领导          一对一/小范围,详略适中,聚焦"卡点和资源"
  - 高管/董事会       极简,只看结论、关键指标、ask

Q3 状态灯口径 (单选)
  - 标准三色          🟢 On Track / 🟡 At Risk / 🔴 Off Track
  - 四色加完成态       上面三色 + ⚪ Done/Not Started
  - 不要状态灯         汇报内容不适合"项目化进度",只列结论和数字
```

如果是"多页汇报序列"，再加 Q4：

```
Q4 页序列 (多选,最少 3 项)
  - 封面/期间页        汇报期间 + 整体状态
  - BLUF 结论页        一句话核心结论
  - KPI 看板页         关键指标 状态灯 + 目标 vs 实际
  - 完成项页           上周/月做了什么
  - 计划项页           下周/月要做什么
  - 风险/阻塞页        当前风险 + 需要的支持
  - 行动项页           who/what/when
  - 附录页（明细数据）  备而不讲
```

---

## Step 3 — 输出 BLUF + 指标 + 行动项方案（不要动手画！）

工作汇报的设计方案核心是三件套：**BLUF（一句结论） + 关键指标列表 + 行动项**。

详细模板见 [design-plan-template.md](design-plan-template.md)。包含：

1. **BLUF**（一句话结论，≤30 字）
2. **支撑指标**（3-5 个，每个含：指标名 + 目标 + 实际 + 状态灯 + 偏差归因）
3. **行动项**（3 个以内，每个含：动作 + 责任人 + deadline）
4. **风险/Ask**（如有，列明白"我需要 XXX 决策/资源"）
5. **输出格式**（HTML / PPTX-OfficeMCP / PPTX-Standalone / PNG）

输出之后问：

```
以上是设计方案,可以开始生成了吗?或者哪里要改?
  □ 可以开始
  □ 改 BLUF
  □ 改某个指标（请说名字）
  □ 改行动项 / 责任人
  □ 改 ask
  □ 改输出格式
```

**用户没说"可以开始"之前，不要进入 Step 4。**

---

## Step 4 — 按选定输出格式执行

- HTML → 见 [../formats/html.md](../formats/html.md)
- PPTX via Office MCP → 见 [../formats/pptx-office-mcp.md](../formats/pptx-office-mcp.md)
- PPTX 独立生成 → 见 [../formats/pptx-standalone.md](../formats/pptx-standalone.md)
- 图片 PNG → 见 [../formats/image-png.md](../formats/image-png.md)

风格具体布局见 [../styles/](../styles/) 对应文件。

---

## Step 5 — 验证 + 用户最终确认

完成后必做：

1. **自检**：按对应 `formats/*.md` 末尾的"验证清单"过一遍，且对照 [anti-patterns.md](anti-patterns.md) 5 条最常踩反模式过一遍
2. **特殊检查（工作汇报专属）**：
   - 状态灯口径全页一致吗？
   - 黄/红状态都有归因说明吗？
   - 行动项都有责任人+deadline 吗？
   - BLUF 是不是"一眼能读完"？
3. **用户确认**：把结果给用户，问"满意吗？想象一下给老板看会被问什么？"

用户说"OK"才算结束。
