# B端行业数字化可行性调研

## 概述

本Skill提供一套经过验证的B端行业数字化产品线可行性调研方法论，帮助团队系统性地回答以下问题：

1. **要不要进入这个行业？** — 市场规模、增长趋势、政策环境
2. **哪些场景可以切入？** — 行业场景全景、竞品格局、差异化空间
3. **每个场景值不值得做？** — 客户视角ROI（好不好卖）+ 己方视角ROI（值不值得做）
4. **按什么路径推进？** — 快赢场景识别、平台化复用、分阶段切入

## 核心方法论：漏斗式递进 + 双视角决策

```
Phase 0: 调研准备
    ↓
Phase 1: 行业全景扫描（宽而浅）
    ↓
Phase 2: 竞品-场景交叉分析（识别机会空间）
    ↓
Phase 3: 场景筛选与聚焦（标注可切入场景）
    ↓
Phase 4: 单场景深度调研（窄而深）
    ↓
Phase 5: 投入产出双视角分析（客户ROI + 己方ROI）
    ↓
Phase 6: 路径规划与决策（Go/No-Go）
```

**双视角ROI**：
- **客户视角**：客户采购方案后能获得的回报（用于售前说服）
- **己方视角**：我方研发生产该方案能获得的利润（用于内部决策）

## 执行流程

### Phase 0: 调研准备

**输入确认**：
- 目标行业名称
- 团队现有能力/基因（如"建筑安全管理"、"IoT平台"、"AI视觉"等）
- 用户是否已有初步调研资料（PDF/Excel/文档）
- 预期交付时间
- 是否需要竞品数据补充（WebSearch预算）

**输出**：
- 调研项目启动确认
- 分阶段交付计划

---

### Phase 1: 行业全景扫描

**目标**：建立行业全局认知，识别产业链结构、政策驱动因素、市场规模

**执行步骤**：

1. **搭建调研框架文档**
   - 生成Word文档《[行业]全景扫描_调研框架》
   - 包含8大模块：
     - 行业概况与发展趋势
     - 政策法规与监管环境
     - 产业链图谱与价值分布
     - 市场主体与竞争格局
     - 技术发展趋势
     - 市场规模与增长预测
     - 数字化转型痛点与机会
     - 切入建议与风险提示

2. **融合用户自有资料**（如有）
   - 读取用户上传的PDF/Excel/文档
   - 提取关键数据：政策清单、产业链节点、竞品名单、业务流程
   - 补充至调研框架，生成V1.1版

3. **补充外部数据**（WebSearch）
   - 搜索行业市场规模、增速、政策文件
   - 搜索主要竞品及其产品布局
   - 搜索行业数字化转型趋势

**输出**：
- 《[行业]全景扫描_调研框架_补充版.docx》
- 行业产业链图谱（文字描述）
- 政策驱动因素清单

---

### Phase 2: 竞品-场景交叉分析

**目标**：识别"哪些场景有需求但竞品少"（蓝海）和"哪些场景竞品密集"（红海）

**执行步骤**：

1. **穷举行业场景**
   - 基于产业链图谱，列出各环节的业务场景
   - 分类：政策驱动场景、产业链场景、新兴场景
   - 每个场景标注：名称、特点、痛点描述

2. **识别竞品阵营**
   - 列出行业内的主要数字化厂商
   - 按背景分类：行业龙头系、互联网系、第三方专业厂商、新兴创业公司

3. **构建交叉矩阵**
   - 纵向：场景（名称+特点+痛点）
   - 横向：竞品阵营及具体厂商
   - 交叉单元格：该厂商对该场景的支持情况（详细描述/市场占有率）
   - 市场占有率标注：红色（极高/70-90%）、橙色（中）、蓝色（低）、空白（无）

4. **矩阵迭代补全**
   - 用户标注缺失场景（截图红框/Excel标注）
   - AI根据反馈补全数据

5. **汇总为Excel**
   - 单表汇总所有场景
   - 增加列：场景类型、资质要求、面向客户、场景可行性
   - 应用条件格式：红橙蓝市场占有率、斑马纹、冻结窗格

**输出**：
- 《[行业]竞品场景交叉矩阵表_完整版.docx》（多表）
- 《[行业]运营侧竞品场景矩阵_汇总表.xlsx》（单表）

---

### Phase 3: 场景筛选与聚焦

**目标**：从全景场景中筛选出"可切入"的重点场景

**执行步骤**：

1. **用户标注可切入场景**
   - 在Excel矩阵的"场景可行性"列标注：
     - "可切入"：有市场空间且团队有能力切入
     - "PASS"：竞品太强或市场太小
     - "观望"：政策不确定或技术不成熟

2. **AI补充场景属性**
   - 填充"有无资质要求"列
   - 填充"面向的具体客户"列

3. **初步可行性排序**
   - 按"可切入"场景数量、市场规模、团队匹配度排序
   - 识别Top 15-20个可深入调研的场景

**输出**：
- 标注完成的Excel矩阵
- 可切入场景清单（15-20个）

---

### Phase 4: 单场景深度调研

**目标**：对每个可切入场景生成可独立使用的售前解决方案文档

**执行方式**：
- 使用Task子代理并行生成（每批3-6个场景）
- 每个场景生成独立的Word文档

**文档结构**（9个章节）：

1. **场景概述与政策背景**
   - 场景定义与边界
   - 相关政策法规梳理
   - 行业痛点分析（3-5个核心痛点）

2. **市场规模与增长趋势**
   - 市场规模数据（2024-2028预测）
   - 增长驱动因素
   - 市场渗透率分析

3. **目标客户画像**
   - 客户类型细分
   - 决策链分析（决策者、影响者、使用者）
   - 采购预算范围
   - 关键决策因素

4. **业务流程与架构设计**
   - 核心业务流程（步骤分解）
   - 系统功能架构（模块划分）
   - 关键技术点
   - 与现有系统的集成点

5. **竞品分析**
   - 主要竞品详细分析
   - 竞品功能对比表（8-10个维度）
   - 市场格局分析
   - 我方差异化优势

6. **商业模式与定价策略**
   - 商业模式选择（SaaS/项目制/混合）
   - 定价参考（按版本/按用量/按功能）
   - ROI分析（客户视角）

7. **实施路径与里程碑**
   - MVP版本（3个月）
   - V2.0版本（6个月）
   - V3.0版本（12个月）
   - 团队配置建议

8. **风险与挑战**
   - 技术风险及应对
   - 市场风险及应对
   - 合规风险及应对

9. **售前解决方案摘要**
   - 一页纸方案概述
   - 核心价值主张（3-5条）
   - 典型客户案例（可构造）

**输出**：
- [场景编号]_[场景名称]_深度调研与售前方案.docx（每场景1份）
- 统一存入文件夹："[行业]场景深度调研/"

---

### Phase 5: 投入产出双视角分析

**目标**：同时回答"客户要不要买"和"我们值不值得做"

#### 5.1 客户视角ROI分析

**执行步骤**：
1. 从各场景深度调研文档中提取ROI数据
2. 汇总为Excel对比表
3. 计算指标：客户投入、客户年收益、投资回收期、5年ROI
4. 按回收期和ROI分级：★★★★★ / ★★★★☆ / ★★★☆☆ / ★★☆☆☆

**输出**：
- 《[行业]场景投入产出比汇总对比.xlsx》
- 4梯队推荐（强推/推荐/可选/观望）

#### 5.2 己方视角ROI分析

**核心假设**（需根据团队实际情况调整）：
- 研发人月成本：2.5万（含薪资、社保、办公分摊）
- 研发投入 = 团队人数 × 周期(月) × 2.5万
- 单项目交付成本 = 实施人员 × 实施周期 × 2.5万 + 第三方成本
- 单项目报价 = 客户视角投入（客户愿意付的钱）
- 毛利率 = (报价 - 交付成本) / 报价
- 可复用模块占比 = 团队已有能力可复用的比例
- 3年目标客户数 = 基于市场规模的保守估计

**计算指标**：
- 研发团队规模、研发周期、研发总投入
- 单项目交付成本、单项目报价、单项目毛利率
- 可复用模块占比、3年目标客户数
- 3年预期总营收、3年预期总利润
- 研发投入回收期

**输出**：
- 《己方视角投入产出分析.xlsx》（3个Sheet）
  - Sheet1: 己方视角ROI主表
  - Sheet2: 双视角对比
  - Sheet3: 关键洞察

---

### Phase 6: 路径规划与决策

**目标**：形成可执行的切入路径和Go/No-Go决策建议

**执行步骤**：

1. **识别平台化机会**
   - 分析18个场景中的共享底层能力
   - 识别可跨场景复用的平台（IoT、AI、数据中台等）
   - 计算平台化节省的研发投入

2. **分阶段切入路径**
   - Phase 1 快赢期（0-6个月）：选择研发投入低、回收快、团队基因匹配的场景
   - Phase 2 平台期（6-12个月）：建设共享平台，复用至更多场景
   - Phase 3 深水期（12-24个月）：切入高利润但需要补齐行业Know-How的场景
   - Phase 4 生态期（24-36个月）：布局新兴场景，建立生态壁垒

3. **Go/No-Go决策建议**
   - 综合双视角ROI、团队匹配度、市场时机
   - 给出明确的决策建议：立即启动 / 启动（需补充能力）/ 跟踪+试点 / 观望

**输出**：
- 切入路径规划文档（可并入最终汇报PPT/Word）
- Go/No-Go决策建议

## 关键设计原则

### 1. 漏斗式递进
- 先宽后深，避免过早聚焦导致方向性错误
- Phase 1-2 建立全局认知，Phase 3-4 聚焦深挖

### 2. 人机协作迭代
- AI生成初稿 → 用户审核反馈（标注/截图/评论） → AI迭代补全
- 用户在矩阵中的标注比AI自行筛选更贴合业务实际

### 3. 矩阵化思维
- 用"场景×竞品"交叉矩阵替代线性列表
- 直观发现红海（竞品密集）和蓝海（竞品空白）

### 4. 双视角决策
- 客户视角ROI：用于售前说服（好不好卖）
- 己方视角ROI：用于内部决策（值不值得做）
- 特别关注"视角差异最大"的机会

### 5. 平台化思维
- 识别跨场景复用的底层能力
- 先建平台再铺场景，降低总体研发投入

## 注意事项

1. **数据时效性**：市场规模、竞品市占率等数据基于WebSearch获取，可能存在滞后，建议定期更新

2. **ROI估算精度**：己方视角ROI基于假设参数（人月成本、复用率、客户数等），实际偏差可能较大，需结合团队实际情况校准

3. **行业深度**：AI对特定行业的认知深度有限，部分业务流程和技术细节可能不够准确，建议行业专家审核

4. **WebSearch预算控制**：
   - 简单任务：1-3次搜索
   - 中等任务：3-5次搜索
   - 复杂任务：5-10次搜索
   - 避免重复搜索，优先批量查询

5. **并行执行**：Phase 4的单场景深度调研建议使用Task子代理并行执行（每批3-6个），提高效率
